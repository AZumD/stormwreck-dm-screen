# Language & terminology

Stormwreck supports two UI languages:

- `sv` — Swedish-first tabletop language, with selected D&D terms kept in English where that is clearer.
- `en` — the original English UI.

The selected language is stored in browser local storage as `stormwreck-language`. Swedish is the default. Switching language reloads the current page so every dynamic module starts against one consistent dictionary instead of producing a half-translated UI.

Date and time formatting follows the selected site language as well: Swedish uses `sv-SE`, while English uses `en-GB`. Existing app code that calls the browser's locale formatting without explicitly requesting another locale therefore stays consistent with the SV/EN switch.

## Translation philosophy

Swedish mode should sound like Swedish people actually talking around a roleplaying table. It should not be literal machine translation, but it also should not assume every RPG term has to stay in English.

Before preserving an English term, check for established Swedish tabletop vocabulary. Useful primary/reference material includes Fria Ligan's Swedish *Drakar och Demoner* material:

- https://freeleaguepublishing.com/sv/shop/drakar-och-demoner/grundspel/
- https://freeleaguepublishing.com/sv/drakar-och-demoner-tredjepartsmaterial/

The current Swedish *Drakar och Demoner* product language explicitly uses terms such as **rollperson**, **färdighet**, **strid**, **magi**, **resor**, **spelledare**, and **initiativ**. Swedish RPG usage also has a long tradition of **grundegenskap**.

D&D-specific mechanics still need D&D-specific judgment. Do not import a term from another Swedish RPG if it would imply that game's mechanics rather than merely translate ordinary vocabulary.

## Architecture

- `js/i18n/en.js` — existing English campaign/UI dictionary.
- `js/i18n/sv.js` — Swedish overlay, including the shared terminology table.
- `js/i18n/sv-creator.js` — creator-specific Swedish vocabulary.
- `js/i18n/language.js` — language selection, persistence, dictionary merge, and switcher.
- `js/i18n/locale.js` — makes implicit browser date/time formatting follow the selected site language.
- `js/i18n/dom-localization.js` — conservative localization of legacy/static chrome without translating user-authored content.
- `js/i18n/player-localization.js` — translates Player Companion UI generated at runtime, including sheet/library/schedule chrome, while deliberately leaving character notes, posts, names and other authored content alone.
- `js/i18n/catalogue-localization.js` — Swedish Compendium/catalogue labels and editor field copy.
- `js/i18n/catalogue-content-i18n.js` — runtime localization layer for built-in Compendium entries, including localized search aliases and edit-preservation checks.
- `js/i18n/catalogue-content-sv-rules.js` — Swedish built-in Rules and Skills reference content.
- `js/i18n/catalogue-content-sv-character.js` — Swedish Background, Species, Class and Feature reference content.
- `js/i18n/catalogue-content-sv-garden.js` — Swedish content for the reusable Feature entries added by the Compendium garden seed.
- `js/i18n/catalogue-content-sv-expansion.js` — Swedish aliases and table-reference copy for the expanded species/lineages and generic SRD bestiary.
- `js/i18n/catalogue-content-sv-spells.js` — Swedish built-in spell reference content.
- `js/i18n/catalogue-content-sv-stormwreck.js` — Swedish Stormwreck NPC, monster, item and location reference content.
- `css/language.css` — global SV/EN switcher styling.

`js/core/catalogue/types.js` is loaded early by most application surfaces and bootstraps the language runtime before downstream UI modules initialize. The root gate and Character Creator have explicit bootstraps because they do not follow the same script path.

## Built-in Compendium content overlays

English catalogue data remains canonical. Swedish Compendium content is a runtime overlay rather than a second persistent catalogue or a migration that rewrites stored entries.

`CatalogueContentI18n.register(type, records)` associates a canonical catalogue ID with Swedish display fields and optional Swedish search aliases. When Swedish mode is active, the runtime decorates known entries with non-enumerable `i18n.sv` and `searchSv` properties and teaches catalogue search to include the Swedish text. Those runtime properties are deliberately non-enumerable so normal catalogue persistence does not write localization metadata into user data.

A translated field is only substituted while the stored value still matches the built-in English/original seed value. If a user edits a built-in entry, that field stops receiving the stock Swedish overlay and the user's edited value wins. Custom entries with no explicit localization record are left alone entirely.

This gives the Compendium three useful properties at once:

1. English and Swedish can share the same stable IDs and `@type:id|Label` references.
2. Swedish searches such as `smyga`, `räddningsslag`, `svår terräng`, or `bronsdrake` can find the same canonical entities as their English counterparts.
3. A future seed/localization update cannot silently translate over a user's custom prose.

Current explicit content coverage includes Rules, Skills, Backgrounds, Species and lineages, Classes, reusable Features, Spells, the generic SRD bestiary, and the built-in Stormwreck NPC/monster/item/location reference set.

## Content boundary

Localization owns **application chrome and built-in reference copy**. It does not silently rewrite user-created content.

Do not auto-translate:

- character names or backstories,
- campaign notes and scene prose,
- message-board posts,
- imported/custom Compendium descriptions,
- IDs, API field names, catalogue IDs, or `@type:id|Label` reference syntax.

Built-in rule/catalogue material may have explicit localized variants, but those should be maintained as localization data rather than mutated in place.

## Adding Compendium reference content

Prefer small, reusable catalogue entities over repeating the same rules explanation inside several races/classes/backgrounds. New built-in seeds should use stable IDs, concise original summaries, and links to existing Compendium entities where useful.

For a browser-visible seed that also needs server materialization, a CommonJS/browser-compatible seed module can be loaded by the Compendium and required by `server/lib/catalogue-seed-sync.js`. Seed synchronization is additive: it creates missing catalogue JSON files but never overwrites existing live entries. This is the preferred pattern for expanding the built-in library without trampling edits.

When a new built-in entry needs Swedish content, register its localized fields in the appropriate `catalogue-content-sv-*.js` pack and add Swedish aliases that reflect what somebody would actually type at the table.

SRD-derived mechanical reference content must keep its provenance visible and follow the attribution in `docs/OPEN-CONTENT.md`. Non-SRD sourcebook options should remain original summaries rather than copied source text.

## Adding new UI copy

Prefer dictionary-backed copy for new functionality rather than adding another hard-coded English string.

For campaign modules already using `window.I18N`, add the English key to `js/i18n/en.js` and the Swedish equivalent to `js/i18n/sv.js`.

For site/platform UI, add the key under `site` in the language dictionaries and consume it through `window.AppI18n.t("site.…", fallback)` or a `data-i18n="site.…"` attribute.

Never translate IDs, API field names, catalogue IDs, `@type:id|Label` reference syntax, or user-authored campaign content.
